# P04 frozen CPU domain interface v1

Scope is synthetic metric review. Runtime never reads evaluations/. Root owns future HTTP/UI/model routing and persistent receipt review. The CPU worker owns data, gold, manifest, metric_review/domain.py and domain tests. No model, network, SQL, shell or file-path parameters enter analyze.

## Inputs
load_snapshot(data_dir) reads ONLY data/mes_counts.json, shift_time.json, scope_manifest.json and metric_catalog.json, verifies the frozen SHA256 entries in data/freeze_manifest.json, and returns {sources:{mes_counts:envelope,shift_time:envelope}, manifest:object, catalog:object, snapshot_hash:str}. Each envelope contains its receipt, schema_version, records and server-computed source_sha256. The loader never reads gold.

analyze(sources, manifest, catalog, *, dataset_id, business_date, as_of_cutoff, authorized_sites, metric_id="oee", shift_ids=None) -> receipt object. authorized_sites is an explicit nonempty collection supplied by the trusted authenticated backend. Rows, expected scope, replay metadata and quarantine are filtered by those sites BEFORE revision selection, joins or arithmetic. No unauthorized row identifier/count/time is returned. Request dataset/date/cutoff/metric/shift values are strict allowlisted selectors. Root handles ambiguous natural requests such as uptime/last shift; no domain guessing. as_of_cutoff requires timezone-aware ISO8601; business_date is explicit ISO date, not inferred from wall clock. The request date must equal the manifest business date.

Sources are the two frozen JSON exports. Catalog approved status/version and approved ideal cycles are mandatory. Exact key is (site_id,line_id,business_date,shift_id,product_id,cycle_version). Explicit scope_manifest expected_keys defines completeness; row count/file length never defines it. No inferred shift start/end is supplied. Overnight uses the explicit export business date and Asia/Seoul metadata.

Historical cutoffs reconstruct exported record-time revisions, NOT what the receiving system knew at that time. issued_at is the source-record timestamp; received_at is the later export receipt timestamp. Receipt1 at 01:00+09 is after both example historical cutoffs. Latest revision is chosen PER source type+record_id after dataset/site/date selection with issued_at <= cutoff. Eligibility filtering occurs BEFORE same-revision conflict detection, so future conflicts cannot taint a historical result. Exact duplicate content at the same revision is a replay and skipped. Conflicting same identity+revision quarantines that identity, without fallback to older rows. Multiple identities mapping to the same join key are an ambiguous join and excluded. No cumulative counts/delta conversion guessing.

## Output
Top-level: {status,rule_version,snapshot_hash,request,receipts,accepted,quarantine,replays,superseded,conversions,coverage,per_shift,combined}.
accepted is {counts:[normalized authorized record],times:[normalized authorized record]}; each record has key, record_id,revision,receipt_id,source_sha256,record_sha256 and values. quarantine/replays/superseded contain authorized source_type/record_id/revision/key/reason only. conversions record explicit source unit s|min, multiplier 1|60 and exact integer input/output strings. receipts hold receipt_id/revision/source_sha256/schema_version, no raw unauthorized values.
coverage contains expected_keys,expected_pairs,accepted_pairs,complete_counts,complete_times,complete_pairs and missing/invalid authorized keys.
per_shift entries have key,metrics,flags. combined has metrics,flags,naive_average_oee and naive_average_gap_percentage_points. Metrics keys availability/performance/quality/oee map to {exact:str|null,percentage_exact:str|null,percentage_4dp:str|null,numerator_exact:str|null,denominator_exact:str|null,undefined_reason:str|null}. Exact values are reduced Fraction strings; no float arithmetic or clamping. Percent strings support UI without Number conversion.
Undefined denominator returns null with zero_denominator. Missing good returns quality/OEE null but availability/performance may be supported. Missing count rows do not prevent availability if ALL expected time rows are valid. Missing time rows do not prevent quality if ALL expected count rows are valid. Performance requires complete count/time pairs; OEE requires complete count/time pairs plus good counts. Invalid/missing expected rows block the corresponding combined metric; valid per-shift metrics remain visible. Mixed products or cycle versions block combined metrics even when rows individually valid. Performance above 1 is flagged, retained as exact value, never clamped.
