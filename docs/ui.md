# Governed shift metric review UI

Native Korean metric workbench with system fonts, compact 14px tables and metadata, 16px long text and form controls, and a 4.5 minimum text-contrast target. Dataset, approved metric, explicit shift scope, business date and offset-bearing source-record cutoff are separate selectors. The fixed table columns show A, B and the requested combined scope. The UI displays only server exact fractions and percentage strings; it never calculates, averages, rounds, clamps, or converts null into zero. Combined OEE, naive shift-average OEE and their percentage-point gap remain distinct.

Coverage comes from the explicit authorized manifest, not row counts or file size. Missing and quarantined expected rows keep affected combined metrics undefined while supported per-shift or independent metrics stay visible. A performance value above100% is retained and flagged. Count/time joins, approved ideal cycles, source-unit conversions, revision resolution, replays and quarantine all remain server/domain decisions.

The source drawer reads the server's authorized originals again before opening. It shows every matching original candidate for the selected record/revision, normalized accepted values or exclusion reason, original-record time, later export-receipt time, join key, source and record hashes, and manifest. Duplicate/conflicting originals are not arbitrarily reduced to a guessed row. The native dialog uses aria-labelledby=evidence-title; its name is verified in the browser accessibility tree. Initial focus is the close control, and both button closing and Escape dismissal return focus to the originating source button. The page explicitly describes historical source-record reconstruction, not knowledge of the receiving system at that time, and supplies no inferred shift start/end.

Optional natural-language routing proposes only metric and shift selectors. Keyword is the default. Choosing the existing localhost model is an explicit user action; the UI worker/browser verification makes zero model requests. A route does not change selectors or calculate. Human acknowledgement and Apply are required before a calculable proposal is applied. Clarification/unsupported proposals remain explicit; model errors do not become silent keyword success. Dataset, business date and cutoff stay manually selected.

Demo analyst/reviewer profiles are labeled synthetic, not SSO. Analyst can calculate and inspect; reviewer separately acknowledges the arithmetic receipt with its expected fingerprint. This acknowledges the receipt and does not certify a factory or a production KPI. Changing selectors hides previous result/review controls until calculation; original historical receipt records remain historical. Source-change stale receipts hide results and reviews. Identity transitions clear prior data immediately; unavailable scopes use neutral messages, without unauthorized original row identifiers/counts. Tokens stay only in memory and Authorization headers.

`python3 scripts/browser_check.py` attaches to existing sandboxed Chrome CDP19085, creates/closes only its own tab, and calls the loopback19084 API. Cases and assertions are separate. It covers baseline weighted aggregation, two correction cutoffs, revision conflict, missing B time, unknown B unit, missing good counts, performance above100%, duplicate replay, A/B scopes, source focus and provenance, proposal/apply separation, reviewer gate and idempotent acknowledgement, dirty-cutoff hiding, timezone-stable date strings, neutral ACL, minimum font sizes, computed text contrast, mobile and zoom-equivalent reflow. It never imports evaluator gold, launches a browser, installs packages, or calls a model. Actual results/screenshots go to `artifacts/browser/`; completed counts must be read from `checks.json` after execution.

Closing returns focus to the originating category when its row list has changed, rather than to an unrelated same-index row. Audit history renders the server's `at` timestamp.

`GET /api/sources` retains its authorized row objects and adds `source_rows_text` for each count/time row: exact `revision_exact`, canonical `record_sha256`, `record_text`, `key_text` and original-record time.
